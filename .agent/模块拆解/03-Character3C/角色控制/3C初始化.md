# 3C 初始化（Character/Controller/Camera）

## 1. 结构（Structure）

**3C 组成：**
```
APlayerController (AuraPlayerController)
├── InputComponent          // 输入处理（Enhanced Input）
├── InputMappingContext     // 输入映射配置
└── PlayerCameraManager     // 镜头管理

    │ 控制
    ▼

APawn (AuraCharacter)
├── CharacterMovementComponent  // 移动
├── CapsuleComponent            // 碰撞
├── SkeletalMeshComponent       // 角色模型
└── ASC (通过 PlayerState)      // 能力系统

    │ 驱动
    ▼

UCameraComponent / SpringArmComponent  // 镜头
```

**与 GAS 的关系：**
```
PlayerState (Owner of ASC)
      │
      ├──> ASC + AttributeSet (数据)
      │
      └──> 被 Character 引用（Avatar）

Character (Avatar)
      │
      ├──> 接受输入（3C）
      │
      └──> 触发 Ability（通过 ASC）
```

## 2. 生命周期 / 完整流程（Lifecycle & Flow）

**整体初始化链：**
```
GameMode::PostLogin()
      │
      ▼
Spawn PlayerController
      │
      ▼
PlayerController::OnPossess(Pawn)
      │
      ▼
Character::PossessedBy(Controller)  [Server only]
      │
      ▼
InitAbilityActorInfo()              [关键]
      │
      ├──> ASC->InitAbilityActorInfo(Owner=PS, Avatar=Char)
      │
      └──> 客户端通过 OnRep_PlayerState() 同样调用
```

**详细时序：**

| 阶段 | Server | Client | 说明 |
|------|--------|--------|------|
| 1 | PC Spawn | PC Spawn | 玩家连接 |
| 2 | Possess | - | Server 授权控制 |
| 3 | PossessedBy() | - | 服务器初始化 ASC |
| 4 | - | PS Replicated | PlayerState 复制到客户端 |
| 5 | - | OnRep_PS() | 客户端初始化 ASC |
| 6 | InitOverlay() | InitOverlay() | HUD 初始化（双方） |

**关键代码：**
```cpp
// Server 端初始化
void AAuraCharacter::PossessedBy(AController* NewController)
{
    Super::PossessedBy(NewController);
    InitAbilityActorInfo();
}

// Client 端初始化
void AAuraCharacter::OnRep_PlayerState()
{
    Super::OnRep_PlayerState();
    InitAbilityActorInfo();
}

// 统一初始化逻辑
void AAuraCharacter::InitAbilityActorInfo()
{
    AAuraPlayerState* AuraPlayerState = GetPlayerState<AAuraPlayerState>();
    check(AuraPlayerState);
    
    UAbilitySystemComponent* ASC = AuraPlayerState->GetAbilitySystemComponent();
    ASC->InitAbilityActorInfo(AuraPlayerState, this);
    
    // 初始化 HUD
    if (AAuraPlayerController* PC = Cast<AAuraPlayerController>(GetController()))
    {
        if (AAuraHUD* HUD = Cast<AAuraHUD>(PC->GetHUD()))
        {
            HUD->InitOverlay(PC, AuraPlayerState, ASC, AuraPlayerState->GetAttributeSet());
        }
    }
}
```

## 3. 职责边界（Responsibility）

| 组件 | ✅ 应该做 | ❌ 不应该做 |
|------|----------|------------|
| **PlayerController** | 处理输入、控制镜头、管理 HUD | 直接修改属性（应通过 ASC） |
| **Character** | 接受控制、触发 Ability、动画 | 持有 ASC（PlayerState 持有） |
| **PlayerState** | 持有 ASC 和 AttributeSet | 处理输入响应（Controller 职责） |
| **ASC** | 管理 Ability、应用 GE | 处理 3C 细节 |

**常见混淆：**
- ❌ Character 直接修改 Health（应通过 ASC Apply GE）
- ❌ Controller 持有 ASC（应是 PlayerState 持有）
- ✅ Character 通过 GetAbilitySystemComponent() 获取 ASC

## 4. 关键原理（Principle）

**Owner vs Avatar 分离**
```cpp
ASC->InitAbilityActorInfo(
    Owner = PlayerState,   // 数据拥有者，跨关卡存在
    Avatar = Character     // 表现载体，可以销毁重生
);
```
- **死亡重生场景**：Character 销毁重建，但 ASC 数据保留
- **换角色场景**：PlayerState 不变，只是 Avatar 切换

**网络同步时机**
- Server 先初始化（PossessedBy）
- Client 后初始化（OnRep_PlayerState）
- 确保双方 ASC 都初始化完成后再操作

**3C 与 GAS 的交互点**
```cpp
// Input -> Ability
void UAuraAbilitySystemComponent::AbilityInputTagPressed(const FGameplayTag& InputTag);

// Ability -> Movement
UAbilityTask_WaitInputPress
UAbilityTask_WaitMovement

// ASC -> HUD
FGameplayAttribute::OnValueChanged -> UI Update
```

## 5. 使用模式（Industry Pattern）

**ASC 所有权策略：**

| 角色类型 | ASC 位置 | InitAbilityActorInfo 时机 |
|---------|---------|------------------------|
| Player | PlayerState | PossessedBy / OnRep_PS |
| AI Enemy | Character | PostInitializeComponents |
| Pet | 独立 Actor | 被召唤时 |
| Vehicle | Vehicle Pawn | 乘客进入时重新绑定 |

**常见初始化问题排查：**
```cpp
// 检查 ASC 是否初始化
if (!ASC->AbilityActorInfo->IsLocallyControlled())
    // 不是本地控制，可能是初始化问题

// 检查 Owner/Avatar
UE_LOG(LogTemp, Log, TEXT("Owner: %s, Avatar: %s"),
    *GetNameSafe(ASC->AbilityActorInfo->OwnerActor),
    *GetNameSafe(ASC->AbilityActorInfo->AvatarActor));
```

**常见坑：**
- **Client 上 ASC 为 null**：忘记在 OnRep_PlayerState 中初始化
- **GE 应用后 UI 不更新**：HUD 初始化时 ASC 还没准备好
- **Ability 无法激活**：Input 绑定在 ASC 初始化之前

**面试常问：**
> "为什么 ASC 放在 PlayerState 而不是 Character？"
> 
> 答：为了持久化 - PlayerState 跨关卡存在，Character 会销毁；死亡重生时数据不丢失；支持换角色不换数据。

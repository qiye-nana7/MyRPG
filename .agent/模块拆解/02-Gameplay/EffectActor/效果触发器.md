# EffectActor 效果触发器

## 1. 结构（Structure）

**组成：**
```cpp
AActor (AAuraEffectActor)
├── SceneComponent (Root)     // 根组件
├── StaticMeshComponent       // 视觉表现（蓝图配置）
├── SphereComponent           // 碰撞触发（蓝图配置）
└── InstantGameplayEffectClass // GE 类配置
```

**继承关系：**
```
AActor
  └── AAuraEffectActor
        └── BP_HealthPotion (蓝图子类)
              ├── 网格：药瓶模型
              ├── 碰撞：SphereCollision
              └── 配置：HealthPotion_GE
```

## 2. 生命周期 / 完整流程（Lifecycle & Flow）

**创建时机：**
- 场景放置（Level 里的实例）
- 运行时 SpawnActor（如掉落物）

**触发流程：**
```
玩家进入碰撞区域
      │
      ▼
OnOverlapBegin (蓝图事件)
      │
      ▼
ApplyEffectToTarget(Player)
      │
      ├──> 获取玩家 ASC
      │
      ├──> MakeEffectContext()
      │
      ├──> AddSourceObject(this)  // 记录来源是血瓶
      │
      ├──> MakeOutgoingSpec()
      │
      ├──> ApplyGameplayEffectSpecToSelf()
      │
      └──> Destroy()  // 血瓶消失
```

**销毁时机：**
- 成功应用 GE 后立即 Destroy
- 或设置生命周期（如 30 秒后消失）

## 3. 职责边界（Responsibility）

| ✅ 应该做 | ❌ 不应该做 |
|----------|------------|
| 检测触发条件（碰撞、距离等） | 直接修改属性（应通过 GE） |
| 调用 GE 应用流程 | 处理复杂的游戏逻辑 |
| 配置 GE 类（TSubclassOf） | 控制玩家输入 |
| 提供 SourceObject（自己） | 修改 UI（应广播事件） |

**分层边界：**
```
EffectActor (Gameplay 层)
      │ 调用
      ▼
ASC::ApplyGameplayEffect (AS 层)
      │ 修改
      ▼
AttributeSet (AS 层)
      │ 广播
      ▼
UI (UI 层)
```

## 4. 关键原理（Principle）

**表现与逻辑分离**
- **C++ 层**：只保留逻辑（ApplyEffectToTarget）
- **蓝图层**：配置表现（网格、碰撞、粒子效果）

**为什么这样设计？**
- 策划/美术可以调整视觉效果，不改代码
- 程序专注逻辑，不受表现变更影响
- 复用性：同一个 C++ 类可以配成血瓶、蓝瓶、炸弹

**SourceObject 的重要性**
```cpp
EffectContext.AddSourceObject(this);
```
- 后续可以查询"这个 Buff 是谁施加的"
- 用于伤害统计、击杀归属
- 血瓶销毁后，上下文里仍然保存着来源信息

## 5. 使用模式（Industry Pattern）

**常见 EffectActor 类型：**

| 类型 | 触发方式 | GE Duration | 用途 |
|------|----------|-------------|------|
| **拾取物** | 碰撞 | Instant | 药水、金币 |
| **区域 Buff** | 持续在区域内 | Duration | 治疗光环、毒雾 |
| **陷阱** | 触发器 | Instant | 地刺、爆炸 |
| **交互物** | 按键交互 | Instant/Duration | 开关、传送门 |

**可扩展设计：**
```cpp
UCLASS()
class AAuraEffectActor : public AActor
{
    // 基础版本：Instant GE
    UPROPERTY(EditAnywhere)
    TSubclassOf<UGameplayEffect> InstantGameplayEffectClass;
    
    // 扩展：Duration GE（区域内持续生效）
    UPROPERTY(EditAnywhere)
    TSubclassOf<UGameplayEffect> DurationGameplayEffectClass;
    
    // 扩展：应用策略
    UPROPERTY(EditAnywhere)
    EEffectApplicationStrategy ApplicationStrategy;
    // OnOverlap, OnBeginOverlap_EndOnEndOverlap, OnInteract
};
```

**常见坑：**
- **在 C++ 里硬编码网格/碰撞**：导致每个效果都要新建 C++ 类
- **忘记检查 ASC**：非角色进入触发区域会崩溃
- **EffectContext 没有 SourceObject**：无法追踪来源
- **重复应用**：玩家一直在碰撞区域内，每帧都触发

**最佳实践：**
```cpp
// 防止重复应用
UPROPERTY()
TSet<TObjectPtr<AActor>> OverlappedActors;

void OnOverlapBegin(AActor* Target)
{
    if (OverlappedActors.Contains(Target)) return;
    OverlappedActors.Add(Target);
    ApplyEffectToTarget(Target);
}
```

**面试常问：**
> "EffectActor 为什么要把表现移到蓝图？"
> 
> 答：职责分离 - C++ 专注逻辑，蓝图专注表现；策划美术可以独立调整视觉效果；提高代码复用性。

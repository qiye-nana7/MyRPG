# 项目模块架构

## 1. 结构（Structure）

```
Source/
├── MyRPGCore/                 # 核心层
│   ├── Public/Types/          # 枚举、结构体定义
│   └── Public/Interfaces/     # 纯接口（如 IInteractable）
│
├── MyRPGAbilitySystem/        # GAS封装层
│   ├── Public/Abilities/      # GameplayAbility 基类
│   ├── Public/Effects/        # GameplayEffect 配置
│   ├── Public/Attributes/     # AttributeSet 实现
│   └── Public/Tasks/          # 自定义 AbilityTask
│
├── MyRPGGameplay/             # 玩法逻辑层
│   └── Public/Interaction/    # 交互系统（EffectActor等）
│
├── MyRPG3C/                   # 角色控制层
│   ├── Public/Characters/     # Character 实现
│   └── Public/Controllers/    # PlayerController/AIController
│
└── MyRPGUI/                   # 表现层
    ├── Public/HUD/            # HUD 类
    └── Public/Widgets/        # UMG 控件
```

## 2. 生命周期 / 完整流程（Lifecycle & Flow）

**编译时依赖链：**
```
Core ──→ AbilitySystem ──→ Gameplay ──→ 3C ──→ UI
         ↑_____________________________________│
         （UI 可监听 ASC 事件，但不直接依赖）
```

**运行时初始化链：**
```
GameMode::InitGame()
  └── PlayerController::OnPossess()
        └── Character::PossessedBy() [Server]
              └── ASC::InitAbilityActorInfo()
                    └── HUD::InitOverlay() [Client]
```

## 3. 职责边界（Responsibility）

| 模块 | ✅ 应该做 | ❌ 不应该做 |
|------|----------|------------|
| **Core** | 定义共享类型、接口 | 依赖任何上层模块 |
| **AbilitySystem** | 封装 GAS 插件，提供项目特定的 Ability/Attribute | 处理具体业务逻辑（如火球术伤害公式） |
| **Gameplay** | 实现具体玩法（EffectActor、技能逻辑） | 直接修改 UI |
| **3C** | 角色控制、输入处理、镜头管理 | 直接修改属性（应通过 ASC） |
| **UI** | 监听数据变化，呈现给玩家 | 修改游戏逻辑（只读） |

## 4. 关键原理（Principle）

**依赖倒置原则（DIP）**
- 上层依赖下层的接口，而非具体实现
- Core 层定义接口，各模块实现

**编译隔离**
- 修改 UI 不会触发 Gameplay 重编译
- 加速迭代，降低耦合风险

**可测试性**
- Gameplay 层可独立单元测试（Mock ASC）
- UI 层可用假数据测试（不依赖真实游戏）

## 5. 使用模式（Industry Pattern）

**常见组织方式：**
- **Runtime/** - 运行时模块
- **Editor/** - 编辑器扩展
- **Developer/** - 仅开发使用

**模块通信方式：**
- **Interface** - Core 定义接口，各模块实现
- **Event/Delegate** - 跨模块广播（如属性变化）
- **GameplayTags** - 松耦合状态标记

**常见坑：**
- 循环依赖：Module A include Module B，Module B 又 include Module A
- 头文件污染：Public 头文件包含过多实现细节
- 模块膨胀：单个模块职责过多，应拆分

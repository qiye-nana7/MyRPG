# GameplayEffect 效果系统

## 1. 结构（Structure）

**组成：**
```
UGameplayEffect (Data Asset)
├── Duration Type          // Instant / Duration / Infinite / Periodic
├── Modifiers[]            // 属性修改规则
├── Execution Calculations // 复杂计算（如暴击伤害）
├── Granted Tags           // 施加时赋予的标签
├── Asset Tags             // 用于查询的标签
└── Cues[]                 // 触发的效果（VFX/SFX）
```

**运行时结构：**
```
FActiveGameplayEffect
├── Spec (FGameplayEffectSpec)
│   ├── Def (UGameplayEffect*)
│   ├── Level (float)
│   └── Context (FGameplayEffectContextHandle)
│       └── SourceObject (谁施加的)
├── StartWorldTime
├── Duration
└── Period (周期触发间隔)
```

## 2. 生命周期 / 完整流程（Lifecycle & Flow）

**创建流程（四行代码）：**
```cpp
// 1. 创建上下文（记录来源信息）
FGameplayEffectContextHandle Context = ASC->MakeEffectContext();
Context.AddSourceObject(this);  // 记录血瓶是来源

// 2. 创建规格（类 + 等级 + 上下文）
FGameplayEffectSpecHandle Spec = ASC->MakeOutgoingSpec(
    HealthPotionEffectClass,  // GE 类
    1.0f,                     // 等级（影响曲线数值）
    Context                   // 上下文
);

// 3. 应用到目标
FActiveGameplayEffectHandle ActiveHandle = 
    ASC->ApplyGameplayEffectSpecToSelf(*Spec.Data.Get());
```

**执行流程：**
```
ApplyGameplayEffect
      │
      ├──> 创建 FActiveGameplayEffect
      │
      ├──> 计算 Modifier 值（Magnitude Calculation）
      │
      ├──> 应用到 AttributeSet
      │      └──> PreAttributeChange / PostAttributeChange
      │
      ├──> 添加 Tags（GrantedTags）
      │
      ├──> 触发 Cues（VFX/SFX）
      │
      └──> 如果是 Duration/Infinite，加入 ActiveEffects 列表
```

**销毁/过期流程：**
```
Duration 结束
      │
      ├──> 恢复 Modifier 值
      │
      ├──> 移除 Tags
      │
      └──> 从 ActiveEffects 列表移除
```

## 3. 职责边界（Responsibility）

| ✅ 应该做 | ❌ 不应该做 |
|----------|------------|
| 定义属性如何被修改 | 直接调用 SetHealth（应通过 GE） |
| 处理持续时间、周期 | 处理游戏高层逻辑（如"死亡"） |
| 赋予/移除 Tags | 控制角色移动（3C 职责） |
| 触发视听效果（Cue） | 处理 UI 显示（应广播事件） |

**边界原则：**
- GE 是**修改属性的配方**，不是**游戏逻辑决策者**
- 所有属性修改必须经过 GE，确保可追溯、可同步

## 4. 关键原理（Principle）

**为什么必须用 GE 修改属性？**

1. **可追溯性（Context）**
   - 知道是谁/什么修改了属性
   - 用于伤害统计、击杀归属

2. **网络同步（Replication）**
   - Server 应用 GE → 自动复制到 Client
   - 客户端预测 + 服务器校正

3. **可扩展性（Modifiers）**
   ```cpp
   // 多种修改方式
   Add      // 加法：+25 Health
   Multiply // 乘法：*1.5 Damage
   Divide   // 除法：/2 Cooldown
   Override // 覆盖：=100 Mana
   ```

4. **持续时间管理（Duration）**
   - Instant：立即生效（治疗药水）
   - Duration：持续一段时间后恢复（Buff）
   - Infinite：永久生效（装备属性）
   - Periodic：周期性触发（Dot 伤害）

**EffectContext 的作用：**
```cpp
FGameplayEffectContext
├── Instigator (Controller)   // 发起者
├── EffectCauser (Actor)      // 效果来源（如血瓶 Actor）
├── SourceObject              // 任意 UObject
└── HitResult                 // 命中信息（用于战斗）
```

## 5. 使用模式（Industry Pattern）

**常见 GE 类型：**

| 类型 | Duration | 用途 | 例子 |
|------|----------|------|------|
| **Instant** | - | 立即修改 | 治疗药水、直接伤害 |
| **Duration** | 10s | Buff/Debuff | 加速、中毒 |
| **Infinite** | ∞ | 永久加成 | 装备属性、升级 |
| **Periodic** | 5s | 持续伤害/治疗 | 灼烧、回血光环 |

**Modifier 配置模式：**
```cpp
// 固定数值
Modifier.Magnitude = 25.0f;
Modifier.Operation = EGameplayModOp::Additive;

// 基于等级曲线
Modifier.Magnitude = ScalableFloat;
ScalableFloat.RowName = "HealthPerLevel";  // 查 DataTable

// 复杂计算（Execution）
Execution = UDamageExecution::StaticClass();
// 在 Execution 里读取攻击力、防御力计算最终伤害
```

**Tag 交互模式：**
```cpp
// GE 施加时赋予 Tag（Granted Tags）
GrantedTags.AddTag(FGameplayTag::RequestGameplayTag("State.Buffed"));

// GE 只能施加给满足条件的 Target（Tag 过滤）
ApplicationTagRequirements.RequireTags.AddTag("State.Alive");
ApplicationTagRequirements.IgnoreTags.AddTag("State.Invulnerable");
```

**常见坑：**
- **忘记 AddSourceObject**：无法追踪来源，伤害统计失效
- **Duration 和 Period 混淆**：Duration 是总持续时间，Period 是触发间隔
- **直接在代码里 SetHealth**：绕过 GE，网络不同步
- **Modifier 运算顺序错误**：先算 Add 还是先算 Multiply？GE 有明确的执行顺序

**面试常问：**
> "为什么不用直接 SetHealth，而要用 GameplayEffect？"
> 
> 答：四个原因 - 可追溯（Context）、可同步（Replication）、可扩展（Modifiers）、可管理（Duration）
